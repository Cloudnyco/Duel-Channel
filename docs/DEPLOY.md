# 部署与联机指南

本页说明怎样架设联机服务器、怎样和朋友一起玩。开服的人 clone 仓库即可（素材包在仓库里，见 [ASSETS.md](ASSETS.md)）；其他玩家只要用浏览器打开开服者给的地址。

## 1. 架构

```
浏览器 ──http / ws──▶ 网关 :8600          页面、大厅（昵称、头像）、匹配队列、群组房间
                        │ POST /create（仅本机）
                        │ /match 对局连接（原样转发）
                        ▼
                     对战实例 :8611…      只监听本机；每个实例可同时承载多场比赛：轮次、押注、结算、排名
```

- **网关**把每场新比赛交给负载最低的实例。对局期间浏览器连接网关的 `/match`，由网关原样转发给对应的实例，所以**只需要网关端口能访问到**。
- 页面通过 HTTPS 打开时（前面有反向代理或内网穿透），大厅和对局都改用 `wss://`；代理只需转发网关端口，并允许 WebSocket 升级。
- 战斗是确定性模拟：实例下发阵容和随机种子并预先算出结果，各客户端用同一份 `shared/sim.js` 重放，结果逐位一致。服务器不需要显卡，CPU 占用很低。
- 单机模式（直接打开文件）和「自娱自乐」不经过服务器。

## 2. 一键开服（推荐）

| 系统 | 怎么启动 |
|---|---|
| Windows | 双击仓库根目录的 `start.cmd`（或在命令行运行 `start.cmd`） |
| Linux / macOS | 在仓库根目录运行 `./start.sh` |
| 任意系统 | `npm run host` 或 `node tools/host.mjs` |

脚本（`tools/host.mjs`）会依次：

1. 检查 Node.js（22 或更新）；
2. 缺依赖时运行 `npm ci`；
3. 页面还没构建，或者代码、数据、素材有更新时，重新构建（第一次会下载两款字体）；
4. 询问是否让局域网（或虚拟局域网）里的朋友加入：选 `y` 监听所有网卡，否则只监听本机；
5. 检查端口没被占用，启动网关和 3 个对战实例；
6. 打印本机地址、朋友可以用的地址（会标出 Tailscale、ZeroTier 等虚拟网卡）和防火墙需要放行的端口，在桌面环境里打开浏览器。

按 Ctrl+C 停止。

| 参数 | 作用 |
|---|---|
| `--lan` / `--local` | 不再询问：监听所有网卡 / 只监听本机（非交互运行时默认只监听本机） |
| `--port 8700` | 网关端口，对战实例随之用 8711 起的端口（默认 8600 / 8611 起） |
| `--instances 5` | 对战实例数（默认 3） |
| `--rebuild` | 强制重新构建页面 |
| `--no-open` | 不打开浏览器 |

### Linux 服务器（无桌面）

```bash
./start.sh --lan --no-open
```

常驻运行可以用 systemd。下面假设仓库在 `/opt/duel-channel`，并且已经用 `./start.sh` 构建过一次页面：

```ini
# /etc/systemd/system/duel-channel.service
[Unit]
Description=Duel Channel server
After=network.target

[Service]
WorkingDirectory=/opt/duel-channel
ExecStart=/usr/bin/node server/launch.mjs --instances 3 --host 0.0.0.0
Restart=on-failure
User=duel

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable --now duel-channel
journalctl -u duel-channel -f        # 查看日志
```

服务器自身不提供 HTTPS，公开架设时请放在反向代理之后，并设置 `TRUST_PROXY=1`，让匹配按玩家的真实地址分桌（见下面的「公平性」）；同时请遵守非商业的使用限制（[NOTICE.md](../NOTICE.md)）。

### 页面怎样加载

网关提供的页面分成两部分：

- **代码**（`public/index.html`）：压缩后约 0.3 MB。每次打开都会向服务器确认有没有更新，没有更新时不重新下载。
- **素材包**（`public/pack/duel-pack.<哈希>.json`）：压缩后约 9 MB。文件名随内容变化，浏览器可以一直缓存。

玩家第一次打开时，开始页会显示素材包的下载进度；之后再打开基本是秒开。更新代码后重新构建，素材没变的话素材包文件名不变，玩家也不用重新下载。

压缩副本（`.br`、`.gz`）在构建时生成，网关按浏览器支持的格式发送。

## 3. 手动开服

```bash
npm ci
npm run build          # 先构建页面（需要素材包）
npm start              # 网关 :8600 + 3 个实例 :8611-8613，都只监听 127.0.0.1
```

打开 <http://127.0.0.1:8600/>。默认只监听本机。

### 参数

```bash
node server/launch.mjs --instances 5        # 5 个对战实例
node server/launch.mjs --port 8700          # 网关 8700，实例从 8711 起
node server/launch.mjs --host 0.0.0.0       # 网关监听所有网卡（局域网联机，见第 4 节）；实例始终只监听本机
```

| 环境变量 | 默认 | 作用 |
|---|---|---|
| `PORT` / `HOST` | 8600 / 127.0.0.1 | 单独启动网关或实例时的端口与地址（`launch.mjs` 会自动设置） |
| `INSTANCES` | 8611,8612,8613 | 网关使用的实例端口（逗号分隔） |
| `QUEUE_FILL_MS` | 10000 | 匹配队列等待多久后由 NPC 补位 |
| `TRUST_PROXY` | 关 | 设为 `1` 时按 `X-Forwarded-For` 的第一跳认定玩家地址（只在反向代理之后开启，否则玩家可以伪造） |
| `QUEUE_SAME_IP` | 关 | 设为 `1` 时允许同一地址的玩家坐同一桌（局域网活动、同一 NAT 后面的多台电脑） |
| `DUEL_DEBUG` | 关 | 设为 `1` 等同 `--debug`：调试模式，见下面的「录制用的调试模式」 |
| `DUEL_BET_MS` / `DUEL_SECRET_MS` / `DUEL_RANK_MS` / `DUEL_RESULT_MS` / `DUEL_SHOW_MS` | 官方值 | 押注时长、其中暗选的时长、计分板、结算面板、开场展示（毫秒，测试用） |
| `BOT_PACE` | 1 | 机器人思考与观战延迟的倍率（测试用） |

### 公平性

- 每轮的战斗种子在押注结束后才发给页面，开局时只给出它的承诺（`sha256(种子:盐)`），页面会核对；押注的最后 7 秒是暗选，这时的选择不公开；知道结果的 NPC 只在暗选时段选择。规则见 [MECHANICS.md](MECHANICS.md)「押注与结算」。
- 公开匹配（礼物对决、竞猜对决的匹配队列）：同一个浏览器同时只能占一个座位（排队中或比赛还在进行时不能再排队）；同一地址的玩家会被分到不同的桌（`QUEUE_SAME_IP=1` 可以关掉）。群组房间由房主邀请，不受这两条限制。
- 限流：大厅和对局连接的消息都有速率上限，持续刷消息的连接会被断开；同一地址每分钟最多输错 10 次房间邀请码。`/status` 只对本机请求显示房间邀请码。
- 机器人（`bots.mjs`）和 NPC 补位不受这些限制影响。

### 录制用的调试模式

录制宣传片等需要提前知道种子的场合，可以开调试模式：

```bash
npm start -- --debug            # 或 DUEL_DEBUG=1 npm start
```

调试模式下每轮的种子随阵容一起下发（和旧版协议相同），进入比赛时会提示，左上角的延迟旁边一直显示「调试模式 · 本场种子提前公开」。不要在公开的服务器上开启。

录制的那台电脑用 <http://127.0.0.1:8600/?debug> 打开页面：不显示上面的提示和标记，画面干净；页面的调试接口 `window.__flow.dbg`（直接调用流程与模拟的内部函数，如 `setupRound`、`predict`、`betPhase`）也只在网址带 `?debug` 或以本地文件（`file:`）打开时可用。

### 状态与健康检查

- <http://127.0.0.1:8600/status>：实例负载、进行中的比赛、匹配队列、房间、最近的服务端错误（`errors`）和收到的错误报告数（`reports`）。
- <http://127.0.0.1:8600/healthz>：`{"ok":true,"instances":N,"page":true}`，供容器与监控使用。页面尚未构建时首页返回 503 并给出提示。

### 日志、错误与自动重启

| 位置 | 内容 |
|---|---|
| 控制台 | 网关、实例和启动器的全部输出 |
| `logs/server-errors.log` | 服务端错误：某场比赛出错、未捕获的异常、未处理的 Promise 拒绝，带时间与调用栈 |
| `logs/reports/*.md` | 玩家在页面里「发送给服务器主机」的错误报告，一份一个文件 |

- 网关或实例遇到未捕获的异常时，会记录后退出，再由启动器自动重启（等待 1、2、4… 秒，最多 30 秒）。同一个进程一分钟内退出超过 5 次就不再重启，控制台会说明原因。实例重启后正在进行的比赛会丢失；网关重启后，玩家页面会自动重连并重新登录大厅。
- 错误报告接口（`POST /report`）：每份最大 64 KB，同一地址每分钟最多 5 份、每小时最多 30 份。
- 日志目录可以用环境变量 `DUEL_LOGS` 指定。Docker 镜像里是 `/app/logs`，需要保留时挂载出来：`-v duel-logs:/app/logs`。

## 4. 和朋友一起玩（局域网）

1. 开服的电脑：运行一键开服脚本并选 `y`（或 `./start.sh --lan`、`start.cmd --lan`；手动方式是 `node server/launch.mjs --host 0.0.0.0`）。
2. 防火墙放行 TCP **8600**（对局连接也走这个端口）：
   - Windows：首次启动时会询问是否允许 Node.js 访问网络，勾选「专用网络」。
   - Linux：`sudo ufw allow 8600/tcp`，或 `sudo firewall-cmd --add-port=8600/tcp`。
3. 其他人用浏览器打开脚本打印的地址 `http://<开服电脑的 IP>:8600/`。
4. 一人「创建群组」得到邀请码，其他人「加入群组」输入邀请码；或者都点「加入赛事」进入匹配队列。

不在同一个局域网时，可以用虚拟局域网工具（例如 Tailscale、ZeroTier、Radmin VPN）把设备组到同一个网络里，再连接虚拟网卡的 IP（脚本会列出来）。**不要**把服务器直接暴露到公网：页面内嵌游戏素材，公开提供属于再分发（见 [NOTICE.md](../NOTICE.md)）。

## 5. Docker

镜像包含服务器、数据，以及用仓库素材包构建好的页面，开箱即玩：

```bash
docker run --rm -p 127.0.0.1:8600:8600 ghcr.io/cloudnyco/duel-channel
```

自己构建：`docker build -t duel-channel .`，再用同样的参数运行 `duel-channel`。

- 容器内网关监听 `0.0.0.0`，端口映射决定谁能访问；上面的写法只对本机开放。局域网联机时把 `127.0.0.1:` 去掉。对战实例只在容器内部使用，不需要映射。
- 想用自己构建的页面，可以挂载进去覆盖：`-v "$PWD/public:/app/public:ro"`。
- 推送 `v*.*.*` 标签时，CI 会把镜像发布到 `ghcr.io/<owner>/duel-channel`。

## 6. 机器人

```bash
node server/bots.mjs --n 7                     # 7 个机器人进入匹配队列（你再进去就满 8 人）
node server/bots.mjs --n 3 --room 123456       # 3 个机器人加入指定房间
node server/bots.mjs --n 6 --loop              # 打完一局继续匹配
node server/bots.mjs --lobby ws://192.168.1.20:8600/lobby --n 4
node server/bots.mjs --n 29 --mode stand       # 29 个机器人进入竞猜对决的匹配队列
node server/bots.mjs --n 30 --mode stand --room new        # 30 个机器人开一个竞猜对决群组（第一个建房，满员开局）
node server/bots.mjs --n 12 --mode stand --room new --npc  # 12 个机器人 + NPC 补位到 30
```

## 7. 常见问题

- **首页显示「尚未构建」**：运行一键开服脚本或 `npm run build`。
- **脚本提示端口已被占用**：多半是已经开着一个服务器，直接打开它的地址；或加 `--port 8700` 换一组端口。
- **开始页提示素材包载入失败**：服务器刚重新构建过，或网络中断，刷新页面即可。
- **页面报错**：右下角会出现「出现了一个错误 · 反馈」，齿轮上有红点；游戏无法继续时会直接弹出错误面板。面板里可以复制报告、打开预先填好的 GitHub Issue，或在联机时发送给服务器主机。也可以随时从「设置 → 反馈问题」打开。
- **匹配成功后卡在加载**：对局连接没有到达实例。经反向代理或内网穿透访问时，检查它是否转发 WebSocket（`/match` 和 `/lobby` 一样需要升级）；服务器控制台和 `/status` 里的 `relays` 可以看到转发中的连接数。
- **标签页切到后台**：页面动画会暂停，服务器照常推进；回到页面后会追上进度（错过的押注按观望处理，对战自动快进）。
- **断线**：
  - 对局中连接中断时，页面显示「等待自己重新联网...」，在 30 秒内自动重连（`maxRetryTimeInBattle`）。服务器会补发断线期间错过的消息（押注、对战、结算），比赛从原处继续。断线期间点的押注会在连上后补发，若押注时间已过则按观望处理。
  - 大厅或房间里断线时，45 秒内（`maxRetryTimeInTeamRoom`）重连会回到原来的房间或匹配队列；其他人会看到你「断线中」。这期间开局的比赛会保留给你。
  - 刷新页面后再点「进入频道」，会直接回到正在进行的比赛（同一个标签页内有效）；比赛刚结束的两分钟内则显示最终结算。
  - 超过时限仍未连上会提示连接失败。比赛中的座位一直保留到比赛结束，期间刷新页面仍可回到比赛。
- **竞猜对决**：匹配与群组都最多 30 人，规则见 [MECHANICS.md](MECHANICS.md)。人凑不齐时可以让机器人陪玩：`node server/bots.mjs --n 20 --mode stand`（进入队列）或 `--room <邀请码>`（进入房间）。单机时由 28 名 NPC 观众陪玩。
- **延迟**：房间页和对战页的延迟每秒测一次，颜色按官方配置的阈值（< 60 ms、60–200 ms、≥ 200 ms）。
